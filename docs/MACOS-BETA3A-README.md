# Hermes macOS · Beta 3a

版本：`1.0.0-beta.3a`，macOS 安装包版本 `1.0.3`。修正 Beta 3 在宽窗口、任务较少和玻璃主题下的布局问题。

## 本轮界面修正

- 首页以统一宽度组织欢迎区、工作概览、最近对话和文件。人物归入欢迎卡片；长文件名在所属区域内换行，摘要隐藏内部上下文标记和附件服务器路径。
- 任务中心以“待你确认／正在执行／最近完成”三列呈现，显示数量与空状态。内容少时收紧看板高度；多任务可分别滚动。点击待处理卡片查看审批或澄清详情。
- 设置页固定合理的表单宽度，分开主题、个人资料；长页提供滚动条。聊天与回看也设定内容宽度，收起文件栏后不会无限拉长。
- 大卡片与小控件使用各自的圆角。修复玻璃主题的胶囊裁切，按逻辑尺寸绘制主题缩略图，适配 Retina 缩放。左侧 64 dp 图标栏融入窗口，移除全高悬浮框和厚重阴影。
- 三套皮肤保留各自的材质与消息编排：哑光连续阅读、纸张纹理和卡片内署名、轻量半透明层次和消息气泡。常用入口保持一致，未调用系统级玻璃模糊效果。
- 文件栏用于聊天和文档工作区。首页和设置不被文件栏挤占；从这些页面点击文件图标，会回到当前聊天并展开文件栏，没有当前聊天时进入文件页。聊天草稿和文档编辑内容继续保留。
- 保留上一版的独立“跳到底部”区域、统一应用弹窗与分类悬停反馈。

截图位于 `docs/previews/beta3a/`，由实际 Compose 代码配合示例数据渲染。问题分析见 [界面检查记录](UI-REVIEW-BETA3A.md)，验证范围见 [验证记录](VALIDATION.md)。本包包含完整源码和启动／打包脚本。

## 从现有版本升级

1. 关闭旧版 Hermes，解压这份 ZIP 到一个新目录，保留整个文件结构。解压后的工程目录是 **Hermes-macOS-beta-3a**；请使用这个新目录。仅把打包脚本复制到旧的 **Hermes-macOS-preview-1** 目录不会升级应用功能。
2. 双击 **Run-Hermes.command**，使用你已经安装好的 **JDK 21**。无需再安装 Homebrew。
3. 原来的登录信息和偏好保存在同一个应用数据目录，启动时会读取；已有待确认事项会迁移到新版状态文件。演示入口仍为 **Preview-Layout.command**。
4. 首次运行可能需要联网补齐本机尚未缓存的依赖。若希望生成可安装的应用，运行 **Package-macOS.command**，输出位于 `build/compose/binaries/main/dmg/`；此入口仅编译应用并打包。需要先跑完整自动测试再打包时，运行 **Build-macOS.command**。

如 Finder 未直接执行脚本，在解压后的项目目录用终端执行对应命令：

```bash
bash Run-Hermes.command
```

脚本会依次识别 `HERMES_JAVA_HOME`、`JAVA_HOME`、系统 JDK、用户 JDK，以及常见的 OpenJDK 21 安装位置；不依赖 `brew` 命令。手动解压的 JDK 可以通过 `HERMES_JAVA_HOME` 指向包含 `bin/javac` 的目录。

JDK 必须为 21，Apple Silicon 使用 ARM64，Intel 使用 x64。首次安装可从 [Temurin JDK 21](https://adoptium.net/temurin/releases/?os=mac&version=21) 选择匹配芯片的 `.pkg`。运行已打包的应用不需要另外安装 Java。

系统识别是可选能力：启动／打包脚本会在已有 Apple Command Line Tools 时编译 `HermesSpeech`。没有这些工具时仍可使用服务器识别和合成；自动模式遇到不支持的服务器接口时，才尝试已有的系统识别组件。

## 操作要点

- `⌘ N` 新对话；`⌘ K` 搜索；`⌘ P` 命令；`⌘ ,` 设置。
- `⌘ Enter` 发送，Enter 换行；`⌘ S` 保存文档；`⌘ W` 收起当前文档。
- 将图片或文本文件拖入窗口，添加到当前聊天。附件上限沿用手机版：10 个，单张图片 8 MB，单份文本 512 KB；服务器文件也可按路径加入对话。
- 任务运行中，“追加要求”发送文字补充；带附件的下一条消息使用“排队”。右侧“助理”标签可以取回、移除或继续队列。
- 深度会审要求服务端真实调用子 Agent；快速会审使用服务端已有的 MoA 模型预设。没有预设时会提示配置，不虚构专家返回。
- 普通麦克风点击开始、再次点击识别。连续语音窗口自动判断停顿，支持打断、回复朗读和继续聆听。识别失败的录音在“设置 → 语音 → 录音记录”中重试或填回草稿。
- 富文本支持标题、强调、列表、引用、代码和表格的常用操作。含嵌套列表、引用式链接、嵌入 HTML 等复杂内容默认进入源码模式，避免富文本转换改变结构。打开后没有编辑的富文本不会改写原文。
- 保存文件前重新读取服务器内容；发现变化会阻止覆盖。本服务接口没有原子条件写入，因此检查和写入之间仍存在很短的并发修改窗口。

## 恢复与本机数据

配置、Cookie、文字与附件草稿、队列、运行标识、未读状态、未保存文档、录音记录和待确认事项均加密保存在本机。大附件与录音采用独立 AES-GCM 数据块；macOS 主密钥存于钥匙串，登录密码不写入本机配置。

数据目录：`~/Library/Application Support/HermesDesktop/`。按网关、账号、Profile 和会话隔离聊天内容。关闭应用前会保存状态；关闭连接不会停止服务器上已经提交的任务。

重新打开后会尝试取回运行结果，不会自动重新提交原问题。恢复任务对应的队列需要点击“继续发送队列”。明确在提交前失败的内容会回到草稿；提交结果不确定时保留恢复记录，防止重复执行。

新版只能恢复新版已经保存过的附件与队列，无法找回旧预览版退出时已经丢失的内存内容。旧预览版没有新版恢复逻辑，因此开始用新版后，不建议两版同时连接同一账号运行。

## 构建与验证

### 测试依赖下载失败时继续打包

新版打包脚本兼容 Preview 1 与 Beta 1 的目录结构。Preview 1 没有 `packaging/prepare-native.sh`，会跳过该版本本来就没有的系统语音组件准备步骤；Beta 1 中组件文件若只存在一部分，脚本会列出缺失的文件并停止。此前“明明与 Build 脚本放在一起却提示放错目录”的问题，是把 Beta 新增文件当成所有版本的必需文件导致的。

脚本会显示当前工程路径和源码版本；在预览工程中运行只会打包预览版。体验本次新增功能，请解压整份 Beta 源码，在新目录运行 `Run-Hermes.command` 或 `Package-macOS.command`。

如果 `Build-macOS.command` 停在 `:compileTestKotlin`，报错包含 `mockito-core-5.14.2.jar` 和 `bad_record_mac`，说明下载测试依赖时发生了 TLS 连接错误。仅凭这条信息无法确定是网络、代理还是 Java TLS 连接的问题。

本版新增 **Package-macOS.command**：准备原生组件和图标，然后调用 [Compose 官方 `packageDmg` 任务](https://kotlinlang.org/docs/multiplatform/compose-native-distribution.html#basic-tasks)，不编译或运行测试，因此不需要 Mockito。生成的仍是当前主程序及其运行依赖，不会减少应用功能。原 **Build-macOS.command** 继续要求测试通过后才打包。

如果已运行过原打包脚本并完成了图标准备，也可以在已配置 JDK 21 的项目终端中直接执行：

```bash
./gradlew packageDmg --console=plain
```

这是避开测试依赖下载的打包入口，不能代表该 Mac 已通过测试，也不修复网络本身。首次下载应用运行依赖仍需联网；若打包中其他依赖也下载失败，保留 `build/logs/package-macos-*.log` 中的具体错误继续排查。没有更改依赖仓库、TLS 设置或证书校验。

### 开发命令

技术版本：Kotlin 2.3.20、Compose Multiplatform 1.10.1、JDK 21、Gradle 8.13。常用命令：

```bash
./gradlew test
./gradlew run
./gradlew run --args="--demo"
./gradlew renderPreviews
```

验证记录见 [VALIDATION.md](VALIDATION.md)，真机步骤见 [MAC-ACCEPTANCE.md](MAC-ACCEPTANCE.md)。测试覆盖真实 HTTP／WebSocket 协议帧的模拟交互、并发会话隔离、恢复状态、附件加密、语音停顿检测、引用和产物解析、编辑内容保护。

安装包在目标 Mac 上生成，按本机芯片打包，未制作 Universal 二合一包。最低构建目标 macOS 13，不处理更老系统兼容。原生资源随安装包打入，使用 [Compose 原生分发机制](https://kotlinlang.org/docs/multiplatform/compose-native-distribution.html)。本次未配置 Developer ID 签名与 Apple 公证，正式对外分发仍需完成这两项和真机验收。

原 Android 工程未修改。资源来源与许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
