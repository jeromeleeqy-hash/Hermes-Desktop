# Hermes Desktop 2.0.4

- 普通介面的連線檢查不再呼叫對話狀態 RPC，也不會因該 RPC 超時而主動切斷即時通道。
- 分別處理普通介面可達性和即時通道恢復；兩次連續連線探測失敗後才顯示伺服器無法訪問。即時通道恢復期間，繼續讀取訊息和對話列表。
- 當前對話定期核對伺服器任務，手機發起的任務在 PC 顯示處理狀態，伺服器明確結束後清除狀態。已知對話的伺服器事件觸發重新整理，輪詢作為兜底。
- 當前對話的未讀標記與正文讀取協調；只有成功讀取正文才推進已讀位置。保留草稿、附件和已經載入的歷史。
- 聊天正文隱藏完整且長度校驗通過的 Hermes App 內部上下文。列表摘要同時處理伺服器截斷的預覽；模型上下文與儲存原文不改寫，程式碼示例和不完整正文保留。
- 恢復連線與同步不會重新提交問題，也不會自動傳送此前保留的排隊訊息。

截圖裡的 PC 顯示缺陷已在程式碼定位；具體那次斷連還需現場連線記錄確認。跨端事件速度取決於閘道是否向 PC 廣播，未廣播時使用輪詢；未聲稱已在使用者真實網路或 macOS / Windows 真機驗證。
