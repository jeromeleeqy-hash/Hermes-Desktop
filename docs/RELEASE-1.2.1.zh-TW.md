# Hermes Windows 1.2.1 · 對話同步修復

本版處理 1.2.0 的“已連上閘道，仍無法同步對話”，以及詳情中的“伺服器返回的對話列表不完整，請稍後重試”。

## 原因

這句異常來自用戶端：收到空對話頁時，只要已讀取位置小於響應的 `total`，就拋錯退出。呼叫方直到整批讀取結束才顯示結果，因此末頁觸發異常後，本輪已讀對話也未顯示。

截圖明確命中了這個判斷分支；僅憑截圖不能確定閘道的 `total` 為何偏大。測試構造了相同條件，用於復現用戶端錯誤，並未冒充真實閘道響應。

## 修復

- 空頁作為分頁結束，不再要求對話數必須等於響應總數。
- 每頁最多 100 條。滿頁繼續讀取，避免偏小的總數提前截斷結果；保留無總數、短頁和重疊頁的處理。
- 普通和歸檔對話逐頁呈現。後續 HTTP 請求失敗時，保留已讀對話和草稿，並顯示失敗狀態；成功完成後才替換舊列表。
- 繼續報告真正的 HTTP 失敗、無效響應和無法前進的重複頁，防止無限請求。
- 錯誤提示不再一律要求檢查網路；詳情增加複製按鈕並附用戶端版本。

## 更新

適用於已有 Windows x64 1.1.0 / 1.2.0 便攜版。更新包只含應用 JAR，不重複下載執行環境。

1. 關閉 Hermes。
2. 將原 `app/hermes-desktop.jar` 備份到 **app 資料夾之外**。
3. 解壓更新包，將其中 `app/hermes-desktop.jar` 覆蓋到原目錄。
4. 使用原 `Start-Hermes.bat` 啟動，在設定中確認版本為 **1.2.1**。

沿用原閘道、賬號和本機草稿；無需刪除使用者資料。需要回退時，關閉程式並還原備份的 JAR。

## 驗證

針對截圖對應分支，修復前的兩項迴歸均失敗；修復後完整測試結果見 `WINDOWS-VALIDATION.md` 與 `validation/windows-1.2.1-tests.json`。

包含使用本機 HTTP 服務連線真實 DesktopController 的測試：阻塞第二頁時首批對話已經顯示；第二頁失敗後保留條目；重試成功恢復正常；空末頁與偏大總數不會再導致錯誤。

構建與自動化驗證在 Linux 完成。未連線使用者真實閘道，未在 Windows 真機執行本包。
