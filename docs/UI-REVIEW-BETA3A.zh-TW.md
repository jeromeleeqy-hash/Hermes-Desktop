# Beta 3a 介面檢查記錄

## 上一版為什麼顯得鬆散、雜亂

1. **沒有建立頁面的內容寬度規則。** 設定頁把 `widthIn` 放在已經由 `weight` 確定寬度的鏈路裡，父佈局的最小寬度覆蓋了預期上限。首頁和聊天也直接跟隨可用寬度伸展。大視窗中標題、檔名、人物和表單控制端點被拉得很遠。
2. **元件邊界混用。** `desktopClick` 預設裁切所有可點選物件，玻璃主題使用百分比 50 的膠囊形狀。主題卡片也繼承這個形狀，文字和縮圖被裁去。縮圖使用物理畫素，Retina 下比例不一致。
3. **缺少稀疏內容的設計。** 任務頁只順序堆放標題和文字，沒有分割槽、數量和明確空狀態。預覽資料很少，卻未專門檢查這種情況。
4. **把材質效果加在錯誤層級。** 給整個導航軌和主面板套浮動邊框、陰影，產生貫穿視窗的大圓角外殼，與內部表單和小控制元件不一致。
5. **摘要沒有應用展示清理。** 移動端內部上下文標記、附件伺服器路徑直接顯示在首頁與歷史列表中。

上一輪驗收主要覆蓋 1440×900、有內容的演示頁面，遺漏了使用者截圖中的 2048 寬視窗、側欄收起、稀疏任務與主題點選後的 Retina 狀態。這些是佈局實現和視覺檢查的問題。

## 本次處理原則

- 在釋放父容器最小寬度約束後限制內容寬度：首頁、歷史、任務最多 1360 dp，設定連同子導航最多 1160 dp，聊天最多 1100 dp。更窄視窗隨可用寬度縮小。
- 用分割槽和對齊組織內容。首頁四個區域共享兩列網格；任務按狀態分列；設定將主題與資料分開。
- 卡片、控制元件、導航分別定義輪廓。卡片裁切顯式使用自己的形狀；主題縮圖用歸一化座標，不再依賴物理畫素尺寸。
- 保留啞光、紙張和半透明層次的差異，避免全視窗多層浮動框。
- 摘要僅清理展示字串，不修改原始訊息、伺服器檔案路徑或訊息提交協議。

截圖和自動檢查是對具體佈局狀態的驗證，不能代替使用者在 Mac 上的使用感受。
