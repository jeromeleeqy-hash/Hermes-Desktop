# Hermes Desktop 2.0.0 Mac 打包修复

日期：2026-10-08；打包修订：r2；应用版本仍为 2.0.0。

## 现象与定位

用户截图中，Finder 打开的名称是 `Hermes-macOS-arm64-2.0.0`，图标为通用应用加禁用标识，提示“可能已损坏或不完整”。

原交付文件实际为 `Hermes-macOS-arm64-2.0.0.app.zip`，并非 DMG。ZIP 顶层有两项：`Hermes.app/` 和 `验收说明.md`。Archive Utility 在为多个顶层项目创建外层目录时，可能沿用去掉 `.zip` 后的名称，使外层也成为 `.app`。外层缺少 `Contents/Info.plist` 和启动入口，符合截图所见现象。尚未取得受影响 Mac 的解压目录或启动日志，因此这是有包结构与截图支持的诊断，不能据此排除其他原生启动问题。

## 修复

- 修订安装包顶层只有 `Hermes.app/`，并显式写入目录条目。
- 应用内所有 534 个原始文件条目保持字节和 Unix 模式一致，保留原签名；删除的是包外说明文件。
- 构建脚本统一使用 `packaging/macos_archive.py`。检查单一应用根目录、Info.plist、真实启动入口、执行权限、ZIP CRC 和安全的符号链接；不允许把外层文件夹当作应用交付。
- 验收说明已存在于应用内 `Contents/Resources/Release/ACCEPTANCE-2.0.0.md`。本次不修改签名后的应用内文件；修订说明随源码提供。
- 源码包及 SHA-256 清单同步更新，未发布 GitHub Release，OSS 继续后置。

## 使用

适用 Apple Silicon（M 系列）Mac、macOS 13 或更新版本。

1. 退出正在运行的 Hermes，包括菜单栏中的后台实例。
2. 解压修订后的 `Hermes-macOS-arm64-2.0.0.app.zip`。
3. 把得到的 **Hermes.app** 拖到“应用程序”，再从那里打开。

若已下载旧包，可先右键那个名称很长的异常应用，选择“显示包内容”。如果里面还有 `Hermes.app`，取出内层应用即可，不必再次下载。该动作不修改用户配置或服务器数据。

若随后出现来源验证提示，应用仍是原来的 ad-hoc 签名状态，未作 Developer ID 公证；这与外层目录无效是不同的检查环节。按 macOS 为该具体应用提供的允许打开流程处理，无需关闭全局系统保护。
