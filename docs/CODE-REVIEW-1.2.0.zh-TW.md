# 1.2.0 程式碼檢查與處理記錄

檢查依據：1.1.0 原始碼和使用者提供的實際 Windows 截圖。實現範圍覆蓋 API 列表讀取、桌面狀態控制、工作台、主導航、聊天輸入、快速查詢和設定。

| 問題 | 處理 | 驗證 |
|---|---|---|
| 前端請求 200 條對話，閘道上限為 100 | API 層限制每頁 100，統一普通與歸檔對話分頁 | 模擬閘道實際拒絕 200 的協議迴歸 |
| 缺少總數時只讀取一頁 | 根據實際頁長度續讀，支援顯式總數的短頁 | 125 條、短頁和重疊頁用例 |
| 重複頁可能迴圈；異常 JSON 被當作空列表 | 重複頁和異常結構明確失敗 | 重複頁、錯誤結構、空頁與剩餘總數用例 |
| 失敗時同時出現“沒有對話” | 載入、錯誤、空狀態分離，保留已讀資料 | home-error / home-loading 渲染斷言 |
| 原始校驗 JSON 直接暴露在頁面 | 提取錯誤描述，頁面顯示可操作提示，原因按需檢視 | 校驗陣列迴歸和錯誤畫面檢查 |
| 舊重新整理結果可能覆蓋新結果 | 同步請求使用遞增序號，只接受當前結果 | 程式碼路徑檢查 |
| 舊訊息載入可能覆蓋剛傳送的一輪 | 啟動新任務時使舊讀取結果失效 | 程式碼路徑檢查；已有任務恢復迴歸 |
| 新建對話連續點選可能重複提交 | 建立期間禁止重複呼叫；失敗解除忙碌狀態 | 程式碼路徑檢查 |
| 首頁附件沒有明確歸屬 | 首頁草稿和附件按工作空間、專案分組；建立成功後一起轉移 | WorkbenchTest 與實際 UI 操作 |
| 附件尚在轉換時可能提前傳送 | 轉換期間阻止首頁與聊天傳送 | 草稿/附件迴歸 |
| 搜尋等待階段出現全部對話；讀取失敗被吞掉 | 等待立即顯示，部分失敗明確提示 | 程式碼路徑檢查 |
| 設定行太寬、開關只能點小區域 | 限制內容寬度，整行開關和可訪問語義；技能響應式兩列 | 設定頁面與 1.5×/2× 渲染 |

新增首頁模板只填入文字，不繞過使用者的傳送操作。已輸入內容不被模板覆蓋。

## 本輪沒有宣稱覆蓋的內容

沒有操作生產閘道、真實麥克風或 Windows 桌面。Windows 真機啟動、系統通知、DPAPI 和 JavaFX 本機視窗仍需實際執行確認。既有全文搜尋範圍仍為最近最多 100 段對話、每段最近 200 條訊息；快速查詢先使用當前工作空間已同步的內容。

沒有更換伺服器端執行、許可權審批、遠端檔案寫前校驗和使用者資料加密方案。它們沿用原有實現和迴歸檢查。
