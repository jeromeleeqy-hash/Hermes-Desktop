# Hermes macOS · Beta 3a

版本：`1.0.0-beta.3a`，macOS 安裝包版本 `1.0.3`。修正 Beta 3 在寬視窗、任務較少和玻璃主題下的佈局問題。

## 本輪介面修正

- 首頁以統一寬度組織歡迎區、工作概覽、最近對話和檔案。人物歸入歡迎卡片；長檔名在所屬區域內換行，摘要隱藏內部上下文標記和附件伺服器路徑。
- 任務中心以“待你確認／正在執行／最近完成”三列呈現，顯示數量與空狀態。內容少時收緊看板高度；多工可分別滾動。點選待處理卡片檢視審批或澄清詳情。
- 設定頁固定合理的表單寬度，分開主題、個人資料；長頁提供捲軸。聊天與回看也設定內容寬度，收起檔案欄後不會無限拉長。
- 大卡片與小控制元件使用各自的圓角。修復玻璃主題的膠囊裁切，按邏輯尺寸繪製主題縮圖，適配 Retina 縮放。左側 64 dp 圖示欄融入視窗，移除全高懸浮框和厚重陰影。
- 三套皮膚保留各自的材質與訊息編排：啞光連續閱讀、紙張紋理和卡片內署名、輕量半透明層次和訊息氣泡。常用入口保持一致，未呼叫系統級玻璃模糊效果。
- 檔案欄用於聊天和文件工作區。首頁和設定不被檔案欄擠佔；從這些頁面點選檔案圖示，會回到當前聊天並展開檔案欄，沒有當前聊天時進入檔案頁。聊天草稿和文件編輯內容繼續保留。
- 保留上一版的獨立“跳到底部”區域、統一應用彈窗與分類懸停反饋。

截圖位於 `docs/previews/beta3a/`，由實際 Compose 程式碼配合示例資料渲染。問題分析見 [介面檢查記錄](UI-REVIEW-BETA3A.zh-TW.md)，驗證範圍見 [驗證記錄](VALIDATION.zh-TW.md)。本包包含完整原始碼和啟動／打包指令碼。

## 從現有版本升級

1. 關閉舊版 Hermes，解壓這份 ZIP 到一個新目錄，保留整個檔案結構。解壓後的工程目錄是 **Hermes-macOS-beta-3a**；請使用這個新目錄。僅把打包指令碼複製到舊的 **Hermes-macOS-preview-1** 目錄不會升級應用功能。
2. 雙擊 **Run-Hermes.command**，使用你已經安裝好的 **JDK 21**。無需再安裝 Homebrew。
3. 原來的登入資訊和偏好儲存在同一個應用資料目錄，啟動時會讀取；已有待確認事項會遷移到新版狀態檔案。演示入口仍為 **Preview-Layout.command**。
4. 首次執行可能需要聯網補齊本機尚未快取的依賴。若希望生成可安裝的應用，執行 **Package-macOS.command**，輸出位於 `build/compose/binaries/main/dmg/`；此入口僅編譯應用並打包。需要先跑完整自動測試再打包時，執行 **Build-macOS.command**。

如 Finder 未直接執行指令碼，在解壓後的專案目錄用終端執行對應命令：

```bash
bash Run-Hermes.command
```

指令碼會依次識別 `HERMES_JAVA_HOME`、`JAVA_HOME`、系統 JDK、使用者 JDK，以及常見的 OpenJDK 21 安裝位置；不依賴 `brew` 命令。手動解壓的 JDK 可以通過 `HERMES_JAVA_HOME` 指向包含 `bin/javac` 的目錄。

JDK 必須為 21，Apple Silicon 使用 ARM64，Intel 使用 x64。首次安裝可從 [Temurin JDK 21](https://adoptium.net/temurin/releases/?os=mac&version=21) 選擇匹配晶片的 `.pkg`。執行已打包的應用不需要另外安裝 Java。

系統識別是可選能力：啟動／打包指令碼會在已有 Apple Command Line Tools 時編譯 `HermesSpeech`。沒有這些工具時仍可使用伺服器識別和合成；自動模式遇到不支援的伺服器介面時，才嘗試已有的系統識別元件。

## 操作要點

- `⌘ N` 新對話；`⌘ K` 搜尋；`⌘ P` 命令；`⌘ ,` 設定。
- `⌘ Enter` 傳送，Enter 換行；`⌘ S` 儲存文件；`⌘ W` 收起當前文件。
- 將圖片或文本檔案拖入視窗，新增到當前聊天。附件上限沿用手機版：10 個，單張圖片 8 MB，單份文本 512 KB；伺服器檔案也可按路徑加入對話。
- 任務執行中，“追加要求”傳送文字補充；帶附件的下一條訊息使用“排隊”。右側“助理”標籤可以取回、移除或繼續佇列。
- 深度會審要求伺服器端真實呼叫子 Agent；快速會審使用伺服器端已有的 MoA 模型預設。沒有預設時會提示配置，不虛構專家返回。
- 普通麥克風點選開始、再次點選識別。連續語音視窗自動判斷停頓，支援打斷、回覆朗讀和繼續聆聽。識別失敗的錄音在“設定 → 語音 → 錄音記錄”中重試或填回草稿。
- 富文本支援標題、強調、列表、引用、程式碼和表格的常用操作。含巢狀列表、引用式連結、嵌入 HTML 等複雜內容預設進入原始碼模式，避免富文本轉換改變結構。開啟後沒有編輯的富文本不會改寫原文。
- 儲存檔案前重新讀取伺服器內容；發現變化會阻止覆蓋。本服務介面沒有原子條件寫入，因此檢查和寫入之間仍存在很短的併發修改視窗。

## 恢復與本機資料

配置、Cookie、文字與附件草稿、佇列、執行標識、未讀狀態、未儲存文件、錄音記錄和待確認事項均加密儲存在本機。大附件與錄音採用獨立 AES-GCM 資料塊；macOS 主金鑰存於鑰匙串，登入密碼不寫入本機配置。

資料目錄：`~/Library/Application Support/HermesDesktop/`。按閘道、賬號、Profile 和對話隔離聊天內容。關閉應用前會儲存狀態；關閉連線不會停止伺服器上已經提交的任務。

重新開啟後會嘗試取回執行結果，不會自動重新提交原問題。恢復任務對應的佇列需要點選“繼續傳送佇列”。明確在提交前失敗的內容會回到草稿；提交結果不確定時保留恢復記錄，防止重複執行。

新版只能恢復新版已經儲存過的附件與佇列，無法找回舊預覽版退出時已經丟失的記憶體內容。舊預覽版沒有新版恢復邏輯，因此開始用新版後，不建議兩版同時連線同一賬號執行。

## 構建與驗證

### 測試依賴下載失敗時繼續打包

新版打包指令碼相容 Preview 1 與 Beta 1 的目錄結構。Preview 1 沒有 `packaging/prepare-native.sh`，會跳過該版本本來就沒有的系統語音元件準備步驟；Beta 1 中元件檔案若只存在一部分，指令碼會列出缺失的檔案並停止。此前“明明與 Build 指令碼放在一起卻提示放錯目錄”的問題，是把 Beta 新增檔案當成所有版本的必需檔案導致的。

指令碼會顯示當前工程路徑和原始碼版本；在預覽工程中執行只會打包預覽版。體驗本次新增功能，請解壓整份 Beta 原始碼，在新目錄執行 `Run-Hermes.command` 或 `Package-macOS.command`。

如果 `Build-macOS.command` 停在 `:compileTestKotlin`，報錯包含 `mockito-core-5.14.2.jar` 和 `bad_record_mac`，說明下載測試依賴時發生了 TLS 連線錯誤。僅憑這條資訊無法確定是網路、代理還是 Java TLS 連線的問題。

本版新增 **Package-macOS.command**：準備原生元件和圖示，然後呼叫 [Compose 官方 `packageDmg` 任務](https://kotlinlang.org/docs/multiplatform/compose-native-distribution.html#basic-tasks)，不編譯或執行測試，因此不需要 Mockito。生成的仍是當前主程式及其執行依賴，不會減少應用功能。原 **Build-macOS.command** 繼續要求測試通過後才打包。

如果已執行過原打包指令碼並完成了圖標準備，也可以在已配置 JDK 21 的專案終端中直接執行：

```bash
./gradlew packageDmg --console=plain
```

這是避開測試依賴下載的打包入口，不能代表該 Mac 已通過測試，也不修復網路本身。首次下載應用執行依賴仍需聯網；若打包中其他依賴也下載失敗，保留 `build/logs/package-macos-*.log` 中的具體錯誤繼續排查。沒有更改依賴倉庫、TLS 設定或證書校驗。

### 開發命令

技術版本：Kotlin 2.3.20、Compose Multiplatform 1.10.1、JDK 21、Gradle 8.13。常用命令：

```bash
./gradlew test
./gradlew run
./gradlew run --args="--demo"
./gradlew renderPreviews
```

驗證記錄見 [VALIDATION.md](VALIDATION.zh-TW.md)，真機步驟見 [MAC-ACCEPTANCE.md](MAC-ACCEPTANCE.zh-TW.md)。測試覆蓋真實 HTTP／WebSocket 協議幀的模擬互動、併發對話隔離、恢復狀態、附件加密、語音停頓檢測、引用和產物解析、編輯內容保護。

安裝包在目標 Mac 上生成，按本機晶片打包，未製作 Universal 二合一包。最低構建目標 macOS 13，不處理更老系統相容。原生資源隨安裝包打入，使用 [Compose 原生分發機制](https://kotlinlang.org/docs/multiplatform/compose-native-distribution.html)。本次未配置 Developer ID 簽名與 Apple 公證，正式對外分發仍需完成這兩項和真機驗收。

原 Android 工程未修改。資源來源與許可見 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
